## DB 설계시 했던 고민
1. auth credential과 users 를 분리?

    비밀번호가 user테이블에 포함되지 않아 추후에 디비가 털려도 조인을 해야 누구의 정보인지 알 수 있고, 다양한 로그인 방법에 대응할 여지를 남기기 위해서

2. menu의 가격을 price와 currency를 나눠 저장하는건 어떨까 

    요즘은 글로벌 고객들도 많으니, 가격 숫자와 통화단위를 분리하는게 맞다고 생각. decimal을 통해 숫자의 정합성을 좀 더 보장하고, 통화는 varchar(3)으로 하여 KRW 와 같이 코드로 저장

3. 주문 기록에 unit_price를 넣는 게 좋겠다

   주문 당시의 가격과 현재 메뉴의 가격이 다를 수 있다. 그래서 기록을 조인으로불러오면 맞지 않을 수 있기에, 해당 시점의 가격을 넣어주는 게 좋아보인다.

4. amount 대신 quantity, 결제에서는 price 대신 total_price를 사용했다.

   최대한 혼동을 줄이고, 단번에 의미가 전달되는 컬럼명으로 수정했다.
